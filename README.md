# Контент-фабрика

Система, которая сама пишет посты и публикует их в сообщества ВКонтакте.
Один пост — обложка с крупным заголовком, две-три дополнительные картинки и
текст. Участие человека в обычный день: одна кнопка в Telegram.

**Сейчас готов Этап 1 — каркас.** Это значит: посты проезжают весь путь от
создания до «публикации», система переживает выключение питания и не делает
одну работу дважды. Но текст, картинки и публикация — заглушки. Ничего не
уходит наружу, ни одного рубля не тратится.

Что появится дальше:

| Этап | Что добавится |
|------|---------------|
| 2 | настоящая публикация в ВК и сборка обложки |
| 3 | настоящие тексты от нейросети |
| 4 | настоящие картинки |
| 5 | Telegram-бот с кнопками «Опубликовать» / «В мусор» |
| 6 | автоответы на комментарии |
| 7 | Docker, автообновление, бэкапы |

## Установка с нуля

Проверено на macOS. Все команды можно копировать целиком.

### 1. Python 3.11

```bash
python3.11 --version
```

Если команда не найдена:

```bash
brew install python@3.11
```

### 2. Менеджер зависимостей `uv`

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

После установки открой новый терминал или выполни:

```bash
export PATH="$HOME/.local/bin:$PATH"
```

### 3. Зависимости проекта

Из каталога с проектом:

```bash
uv sync
```

### 4. Где система будет хранить данные

По умолчанию это `/data` — такой путь рассчитан на запуск в контейнере, и на
обычном компьютере он не создаётся без прав администратора. Для работы на своей
машине задай свой каталог:

```bash
export FACTORY_DATA_DIR=~/factory-data
export FACTORY_PROJECTS_DIR=$(pwd)/projects
```

Эти две строки нужны в каждом новом терминале. Чтобы не повторять, добавь их в
конец файла `~/.zshrc`.

## Первый запуск: от пустой базы до опубликованного поста

Дальше — режим проверки. Публикация ненастоящая: посты складываются в файлы, в
ВКонтакте ничего не уходит.

### Шаг 1. Создать базу

```bash
uv run factory init
```

Ответ:

```
База готова: /Users/ты/factory-data/factory.db (версия схемы 1)
```

### Шаг 2. Подключить учебный проект

```bash
uv run factory project add demo
```

```
Проект 'demo' подключён. Публикаций в сутки: 2, постов в работе: 6.
```

### Шаг 3. Загрузить темы

Темы — это список того, о чём писать. Одна строка — одна тема.

```bash
cat > ~/topics.txt <<'КОНЕЦ'
Как выбрать шины на зиму
Почему греется двигатель
Что делать при проколе
Когда менять масло
Как мыть машину зимой
Что возить в багажнике
Как не купить битую машину
Зачем нужен видеорегистратор
Как экономить топливо
Что делать если сел аккумулятор
КОНЕЦ

uv run factory topics import demo ~/topics.txt
```

```
Загружено тем: 10. Пропущено (пустые и повторы): 0.
```

### Шаг 4. Ускорить время и отключить расписание

Обычно система публикует в 19:30 и 21:00 и делает один шаг раз в десять минут.
Ждать этого при проверке невозможно, поэтому на время:

```bash
export FACTORY_TICK_INTERVAL_SEC=5
export FACTORY_IGNORE_SCHEDULE=1
```

Вторая переменная выключает расписание. Пока она включена, при каждом проходе в
логах появляется предупреждение — это нарочно, чтобы её не забыли выключить.

### Шаг 5. Запустить

```bash
uv run factory run --loop
```

Пойдут строки вида:

```
{"ts": "...", "level": "INFO", "msg": "пост создан", "post_id": 1, "topic_id": 1}
{"ts": "...", "level": "INFO", "msg": "промпты сцен готовы", "post_id": 1, "count": 4}
{"ts": "...", "level": "INFO", "msg": "пост опубликован", "post_id": 1, "external_id": "stub_1"}
```

Через минуту нажми `Ctrl+C`.

### Шаг 6. Посмотреть результат

```bash
uv run factory post list demo
```

```
    8  approved        Зачем нужен видеорегистратор
    7  approved        Как не купить битую машину
    6  approved        Что возить в багажнике
    5  approved        Как мыть машину зимой
    4  approved        Когда менять масло
    3  approved        Что делать при проколе
    2  published       Почему греется двигатель
    1  published       Как выбрать шины на зиму
```

Два поста опубликованы, остальные ждут: в конфиге стоит лимит — две публикации
в сутки. Заголовки совпадают с темами, потому что тексты пока пишет заглушка;
с Этапа 3 их будет придумывать нейросеть.

```bash
uv run factory post show 1
```

Покажет заголовок, полный текст, список из четырёх картинок и сколько потрачено
(на этом этапе — ноль).

Заглушка публикатора складывает то, что «ушло бы» в группу, в файлы — их можно
открыть и прочитать:

```bash
ls "${FACTORY_TMP_DIR:-/tmp/factory}/published/"
cat "${FACTORY_TMP_DIR:-/tmp/factory}/published/post_1.json"
```

### Шаг 7. Убедиться, что система переживает выключение

```bash
uv run factory run --loop
```

В другом окне терминала:

```bash
pkill -9 -f "factory run --loop"
```

Убедись, что никого не осталось:

```bash
pgrep -f "factory run --loop" || echo "воркеров не осталось"
```

Снова запусти:

```bash
uv run factory run --once
```

Посты продолжат движение с того места, где остановились. Уже сделанная работа
не повторяется.

### Шаг 8. Вернуть боевые настройки

```bash
unset FACTORY_TICK_INTERVAL_SEC
unset FACTORY_IGNORE_SCHEDULE
```

Проверить, что всё в порядке:

```bash
uv run factory doctor
```

## Публикация в ВК: нужны ДВА ключа

Это главная неожиданность проекта, и лучше узнать о ней здесь, чем в бою.

ВКонтакте развёл права по типам ключей так, что **ни один не проходит цепочку
публикации целиком**:

| Ключ | Что умеет | Чего не умеет |
|------|-----------|---------------|
| **сообщества** (`VK_TOKEN_GROUP`) | публиковать пост | загружать картинки — отказ на всех шести способах |
| **пользователя** (`VK_UPLOAD_TOKEN`) | загружать картинки | публиковать — отказ как «не-standalone приложению» |

Поэтому система использует оба: картинки грузит один, публикует другой. Пост при
этом выходит от имени сообщества, а не от человека.

**Ключ пользователя живёт 24 часа.** Право `offline`, делавшее его бессрочным,
ВКонтакте отменил. Раз в сутки его надо обновлять — рецепт в
[RUNBOOK.md](RUNBOOK.md) → «Обновить ключ загрузки ВК», занимает минуту.

Что перепробовано и почему больше ничего не выйдет — в
[docs/ВК-как-это-работает.md](docs/ВК-как-это-работает.md). Там же коды всех
ошибок и полная последовательность вызовов.

Рабочий пример конфига с двумя ключами —
[projects/vk_demo/config.yaml](projects/vk_demo/config.yaml).

## Какие ключи понадобятся дальше

Ключи кладутся в файл `~/factory-data/.env`, по строке на ключ, права
`chmod 600`. В репозиторий они не попадают никогда.

| Что | Откуда взять | С какого этапа |
|-----|--------------|----------------|
| Ключ сообщества ВК | Управление сообществом → Работа с API → Ключи доступа | 2 |
| Ключ пользователя ВК | по ссылке из RUNBOOK, обновлять раз в сутки | 2 |
| Ключ LLM | личный кабинет провайдера или реселлера | 3 |
| Токен Replicate | replicate.com → Account → API tokens | 4 |
| Токен Telegram-бота | напиши @BotFather, команда `/newbot` | 5 |

Образец файла — [.env.example](.env.example).
