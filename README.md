# Контент-фабрика

Система, которая сама пишет посты и публикует их в сообщества ВКонтакте.
Один пост — обложка с крупным заголовком, две-три дополнительные картинки и
текст. Участие человека в обычный день: одна кнопка в Telegram.

**Сейчас готов Этап 1 — каркас.** Это значит: посты проезжают весь путь от
создания до «публикации», система переживает выключение питания и не делает
одну работу дважды. Но текст, картинки и публикация — заглушки. Ничего не
уходит наружу, ни одного рубля не тратится.

Что появится дальше:

| Этап | Что добавится |
|------|---------------|
| 2 | настоящая публикация в ВК и сборка обложки |
| 3 | настоящие тексты от нейросети |
| 4 | настоящие картинки |
| 5 | Telegram-бот с кнопками «Опубликовать» / «В мусор» |
| 6 | автоответы на комментарии |
| 7 | Docker, автообновление, бэкапы |

## Установка с нуля

Проверено на macOS. Все команды можно копировать целиком.

### 1. Python 3.11

```bash
python3.11 --version
```

Если команда не найдена:

```bash
brew install python@3.11
```

### 2. Менеджер зависимостей `uv`

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

После установки открой новый терминал или выполни:

```bash
export PATH="$HOME/.local/bin:$PATH"
```

### 3. Зависимости проекта

Из каталога с проектом:

```bash
uv sync
```

### 4. Где система будет хранить данные

По умолчанию это `/data` — такой путь рассчитан на запуск в контейнере, и на
обычном компьютере он не создаётся без прав администратора. Для работы на своей
машине задай свой каталог:

```bash
export FACTORY_DATA_DIR=~/factory-data
export FACTORY_PROJECTS_DIR=$(pwd)/projects
```

Эти две строки нужны в каждом новом терминале. Чтобы не повторять, добавь их в
конец файла `~/.zshrc`.

## Первый запуск: от пустой базы до опубликованного поста

Дальше — режим проверки. Публикация ненастоящая: посты складываются в файлы, в
ВКонтакте ничего не уходит.

### Шаг 1. Создать базу

```bash
uv run factory init
```

Ответ:

```
База готова: /Users/ты/factory-data/factory.db (версия схемы 1)
```

### Шаг 2. Подключить учебный проект

```bash
uv run factory project add demo
```

```
Проект 'demo' подключён. Публикаций в сутки: 2, постов в работе: 6.
```

### Шаг 3. Загрузить темы

Темы — это список того, о чём писать. Одна строка — одна тема.

```bash
cat > ~/topics.txt <<'КОНЕЦ'
Как выбрать шины на зиму
Почему греется двигатель
Что делать при проколе
Когда менять масло
Как мыть машину зимой
Что возить в багажнике
Как не купить битую машину
Зачем нужен видеорегистратор
Как экономить топливо
Что делать если сел аккумулятор
КОНЕЦ

uv run factory topics import demo ~/topics.txt
```

```
Загружено тем: 10. Пропущено (пустые и повторы): 0.
```

### Шаг 4. Ускорить время и отключить расписание

Обычно система публикует в 19:30 и 21:00 и делает один шаг раз в десять минут.
Ждать этого при проверке невозможно, поэтому на время:

```bash
export FACTORY_TICK_INTERVAL_SEC=5
export FACTORY_IGNORE_SCHEDULE=1
```

Вторая переменная выключает расписание. Пока она включена, при каждом проходе в
логах появляется предупреждение — это нарочно, чтобы её не забыли выключить.

### Шаг 5. Запустить

```bash
uv run factory run --loop
```

Пойдут строки вида:

```
{"ts": "...", "level": "INFO", "msg": "пост создан", "post_id": 1, "topic_id": 1}
{"ts": "...", "level": "INFO", "msg": "промпты сцен готовы", "post_id": 1, "count": 4}
{"ts": "...", "level": "INFO", "msg": "пост опубликован", "post_id": 1, "external_id": "stub_1"}
```

Через минуту нажми `Ctrl+C`.

### Шаг 6. Посмотреть результат

```bash
uv run factory post list demo
```

```
    8  approved        Зачем нужен видеорегистратор
    7  approved        Как не купить битую машину
    6  approved        Что возить в багажнике
    5  approved        Как мыть машину зимой
    4  approved        Когда менять масло
    3  approved        Что делать при проколе
    2  published       Почему греется двигатель
    1  published       Как выбрать шины на зиму
```

Два поста опубликованы, остальные ждут: в конфиге стоит лимит — две публикации
в сутки. Заголовки совпадают с темами, потому что тексты пока пишет заглушка;
с Этапа 3 их будет придумывать нейросеть.

```bash
uv run factory post show 1
```

Покажет заголовок, полный текст, список из четырёх картинок и сколько потрачено
(на этом этапе — ноль).

Заглушка публикатора складывает то, что «ушло бы» в группу, в файлы — их можно
открыть и прочитать:

```bash
ls "${FACTORY_TMP_DIR:-/tmp/factory}/published/"
cat "${FACTORY_TMP_DIR:-/tmp/factory}/published/post_1.json"
```

### Шаг 7. Убедиться, что система переживает выключение

```bash
uv run factory run --loop
```

В другом окне терминала:

```bash
pkill -9 -f "factory run --loop"
```

Убедись, что никого не осталось:

```bash
pgrep -f "factory run --loop" || echo "воркеров не осталось"
```

Снова запусти:

```bash
uv run factory run --once
```

Посты продолжат движение с того места, где остановились. Уже сделанная работа
не повторяется.

### Шаг 8. Вернуть боевые настройки

```bash
unset FACTORY_TICK_INTERVAL_SEC
unset FACTORY_IGNORE_SCHEDULE
```

Проверить, что всё в порядке:

```bash
uv run factory doctor
```

## Публикация в ВК: нужны ДВА ключа

Это главная неожиданность проекта, и лучше узнать о ней здесь, чем в бою.

ВКонтакте развёл права по типам ключей так, что **ни один не проходит цепочку
публикации целиком**:

| Ключ | Что умеет | Чего не умеет |
|------|-----------|---------------|
| **сообщества** (`VK_TOKEN_GROUP`) | публиковать пост | загружать картинки — отказ на всех шести способах |
| **пользователя** (`VK_UPLOAD_TOKEN`) | загружать картинки | публиковать — отказ как «не-standalone приложению» |

Поэтому система использует оба: картинки грузит один, публикует другой. Пост при
этом выходит от имени сообщества, а не от человека.

**Ключ пользователя живёт 24 часа.** Право `offline`, делавшее его бессрочным,
ВКонтакте отменил. Раз в сутки его надо обновлять — но руками лезть в файлы не
придётся: когда ключ истечёт, бот напишет вам в Telegram и приложит ссылку.
Останется открыть её, нажать «Разрешить» и переслать боту адрес из строки
браузера. Ключ подставится сам, публикация продолжится без перезапуска.

Способ руками, на случай если бот не работает, — в
[RUNBOOK.md](RUNBOOK.md) → «Обновить ключ загрузки ВК».

Что перепробовано и почему больше ничего не выйдет — в
[docs/ВК-как-это-работает.md](docs/ВК-как-это-работает.md). Там же коды всех
ошибок и полная последовательность вызовов.

Рабочий пример конфига с двумя ключами —
[projects/vk_demo/config.yaml](projects/vk_demo/config.yaml).

## Telegram-бот: одобрение постов с телефона

Готовый пост приходит вам в Telegram: сначала картинки альбомом, потом текст с
кнопками.

```
[✅ Опубликовать]        [🔄 Картинки заново]
[🎲 Другие сцены]        [✏️ Текст заново]
[🗑 В мусор]
```

Что делает каждая:

| Кнопка | Что происходит |
|--------|----------------|
| Опубликовать | пост уходит в группу в ближайший слот расписания |
| Картинки заново | те же сцены рисуются заново, текст сохраняется |
| Другие сцены | сцены придумываются заново, текст сохраняется |
| Текст заново | текст пишется с нуля на ту же тему; сцены и картинки тоже, они сочинялись под старый текст |
| В мусор | спросит, что именно выбросить — пост или пост вместе с темой |

**«В мусор» переспрашивает.** Приходят два варианта:

- **«Только этот пост»** — тема возвращается в очередь, но в конец. Дойдёт
  очередь — попробуем ещё раз, а не прямо сейчас;
- **«Пост и тему»** — тема закрывается, больше по ней не пишем.

Это единственное необратимое действие среди кнопок, и оно стоит вплотную к
остальным — поэтому не срабатывает от одного нажатия.

Нажали откат — сразу приходит «вернусь через пару минут с новым вариантом».
Это сообщение исчезает, когда вариант готов: ждать в тишине не приходится, а
обещание не остаётся висеть под уже пришедшим постом.

После одобрения все кнопки заменяются одной — **«↩️ Отменить публикацию»**. До
ближайшего слота может пройти полдня, и всё это время вы вправе передумать.
Когда пост выйдет, кнопка пропадает и приходит ссылка на публикацию.

Под сообщением о сломанном посте — **«🔧 Попробовать снова»**.

Если нажать кнопку, которая устарела (состояние поста поменялось из другого
сообщения или из командной строки), бот скажет, что с постом на самом деле, и
сам обновит кнопки под ним. Мёртвых сообщений не остаётся.

### Всё нужное — из переписки, без терминала

| Что нужно | Как |
|-----------|-----|
| посмотреть, что происходит | `/status` |
| сколько тем осталось | `/topics` |
| добавить темы | прислать списком, по теме в строке |
| публиковать сразу, не ждать слота | `/schedule_off`, вернуть — `/schedule_on` |
| остановить выпуск | `/pause`, вернуть — `/resume` |
| починить сломанный пост | кнопка под сообщением о поломке |
| обновить ключ ВК | переслать адрес после входа по ссылке |

Темы бот переспрашивает, прежде чем добавить: случайно отправленное сообщение
иначе молча попало бы в очередь и однажды вышло постом.

**Пауза останавливает проект целиком** — ни новых постов, ни публикаций. Уже
одобренные тоже подождут до `/resume`.

### Варианты: посмотреть другой, не потеряв этот

Нажали «Текст заново» или «Другие сцены» — приходит **новый вариант отдельным
сообщением**, а прежний остаётся в переписке. В заголовке видно, какой из
скольких: «Вариант 2 из 3».

На каждом варианте своя кнопка **«Опубликовать этот»**. Пролистали вверх,
нашли тот, что понравился больше, нажали — в группу уйдёт именно он, со своим
текстом и своими картинками.

Вариантов можно наделать сколько угодно: каждый хранится целиком и ничего не
затирает. После публикации все они удаляются вместе с файлами.

Почему варианты не листаются стрелками в одном сообщении: Telegram не умеет
подменять картинки в отправленном альбоме. Текст переключался бы, а картинки
оставались от первого варианта — и показывали бы не то, что вы собираетесь
публиковать.

### Поправить текст руками

Модель написала складно, но одно слово не то. Переписывать весь пост из-за
этого не нужно: **ответьте на сообщение с постом своим вариантом**, и он
заменит текст.

Как бот понимает присланное:

| Что прислали | Что получится |
|--------------|---------------|
| просто текст | заменится текст, заголовок останется прежним |
| строка, пустая строка, текст | заменятся и заголовок, и текст |

Заголовок печатается на обложке, поэтому при его смене обложка собирается
заново и картинки приходят повторно. Если менялся только текст — придёт одно
сообщение с новым текстом и кнопками, картинки второй раз не полетят.

Первая строка длиннее 60 символов заголовком не считается: столько на обложку
не помещается. Тогда всё присланное станет текстом.

### Команды

Список открывается по «/» — Telegram показывает его выпадашкой:

| Команда | Что делает |
|---------|------------|
| `/status` | что происходит прямо сейчас |
| `/topics` | что в запасе, что в работе, что уже вышло |
| `/schedule` | посты выходят сразу или ждут слота |
| `/schedule_on` / `/schedule_off` | переключить это |
| `/pause` / `/resume` | остановить и продолжить выпуск |
| `/start` | что это за бот |

### Как завести бота

1. Написать [@BotFather](https://t.me/BotFather) команду `/newbot`, придумать
   имя. В ответ придёт токен вида `8123456789:AAH...`.
2. Положить его в файл секретов:
   ```bash
   printf 'TELEGRAM_BOT_TOKEN=СЮДА_ТОКЕН\n' >> ~/factory-data/.env
   chmod 600 ~/factory-data/.env
   ```
3. Узнать своё число: написать [@userinfobot](https://t.me/userinfobot).
4. Вписать его в `projects/<slug>/config.yaml`:
   ```yaml
   review:
     mode: telegram

   telegram:
     chat_id: 123456789        # куда приходят посты
     reviewers: [123456789]    # кто может нажимать кнопки
   ```
5. **Открыть своего бота и отправить ему `/start`.** Без этого сообщения не
   дойдут: Telegram запрещает боту писать первым.
6. Запустить бота рядом с воркером:
   ```bash
   nohup ./.venv/bin/factory bot > ~/factory-data/bot.log 2>&1 &
   ```

`reviewers` пустым быть не может. Бот находится в Telegram обычным поиском, и
без списка кнопка «Опубликовать» в вашу группу доступна каждому, кто на него
наткнулся.

### Процессов два

Воркер готовит посты и отправляет их вам. Бот принимает нажатия. Работать должны
оба: при выключенном боте посты приходят, но кнопки не срабатывают; при
выключенном воркере нажатия принимаются, но работу по ним никто не делает.

Нажатия, сделанные при выключенном боте, не теряются — Telegram придержит их до
суток.

## Какие ключи понадобятся дальше

Ключи кладутся в файл `~/factory-data/.env`, по строке на ключ, права
`chmod 600`. В репозиторий они не попадают никогда.

| Что | Откуда взять | С какого этапа |
|-----|--------------|----------------|
| Ключ сообщества ВК | Управление сообществом → Работа с API → Ключи доступа | 2 |
| Ключ пользователя ВК | по ссылке из RUNBOOK, обновлять раз в сутки | 2 |
| Ключ LLM | личный кабинет провайдера или реселлера | 3 |
| Токен Replicate | replicate.com → Account → API tokens | 4 |
| Токен Telegram-бота | напиши @BotFather, команда `/newbot` | 5 |

Образец файла — [.env.example](.env.example).
