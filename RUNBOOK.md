# RUNBOOK — рецепты на каждый день

Сборник «хочу сделать X → выполни это». Команды можно копировать целиком.

Во всех рецептах предполагается, что ты в каталоге проекта и выполнил:

```bash
export PATH="$HOME/.local/bin:$PATH"
export FACTORY_DATA_DIR=~/factory-data
export FACTORY_PROJECTS_DIR=$(pwd)/projects
```

Чтобы не повторять это каждый раз, добавь три строки в конец `~/.zshrc`.

> **Что доступно на Этапе 1.** Рецепты ниже работают уже сейчас. Разделы про
> Telegram, реальную публикацию и Docker появятся на этапах 5, 2 и 7 —
> они помечены как **позже**.

## Ежедневное

### Запустить всё

```bash
uv run factory run --loop
```

Работает, пока открыт терминал. Остановить — `Ctrl+C`: система доделает текущий
проход и остановится, ничего не потеряв.

Чтобы работало в фоне и не зависело от терминала:

```bash
nohup ./.venv/bin/factory run --loop > ~/factory-data/worker.log 2>&1 &
echo $! > ~/factory-data/worker.pid
```

Здесь не `uv run`: он запускает воркер отдельным дочерним процессом и в
`worker.pid` попал бы номер самого `uv`, а не воркера. Обычная остановка через
`uv` ещё работает, а аварийная — уже нет, и получилось бы два воркера сразу.

**Процессов два, и нужны оба.** Воркер готовит посты и отправляет их вам, бот
принимает нажатия кнопок:

```bash
nohup ./.venv/bin/factory bot > ~/factory-data/bot.log 2>&1 &
echo $! > ~/factory-data/bot.pid
```

Что будет, если работает только один:

| Работает | Что происходит |
|----------|----------------|
| только воркер | посты готовятся и приходят в Telegram, но кнопки не срабатывают |
| только бот | нажатия принимаются и меняют состояние, но работу по ним никто не делает |

Нажатия, сделанные при выключенном боте, не пропадают: Telegram придержит их до
суток и отдаст, когда бот вернётся.

### Остановить всё

```bash
kill "$(cat ~/factory-data/worker.pid)"
kill "$(cat ~/factory-data/bot.pid)"
```

Обычная остановка, а не убийство: текущий проход доработает до конца.

Проверь, что действительно остановился:

```bash
pgrep -f "factory run --loop" || echo "воркеров не осталось"
```

Если процесс не откликается больше минуты:

```bash
pkill -9 -f "factory run --loop"
sleep 1
pgrep -f "factory run --loop" || echo "воркеров не осталось"
uv run factory unlock
```

`pkill` по маске, а не по номеру из файла: так добиваются все воркеры, включая
случайно запущенные из другого терминала. Последняя команда снимает блокировку,
оставшуюся от убитого процесса.

**Проверь вывод последней строки.** Если воркеры остались, а ты снимешь
блокировку и запустишь ещё один, — они будут работать параллельно, и защита от
дублей перестанет действовать.

### Посмотреть, что происходит прямо сейчас

```bash
uv run factory doctor
```

Покажет: где база, когда последний раз отрабатывал воркер, сколько тем осталось
у каждого проекта, не идёт ли прямо сейчас проход.

```bash
uv run factory post list demo
```

Последние двадцать постов и их состояния.

### Посмотреть логи

Все за последнее время:

```bash
tail -n 200 ~/factory-data/worker.log
```

Следить вживую:

```bash
tail -f ~/factory-data/worker.log
```

Только ошибки и предупреждения:

```bash
grep -E '"level": "(ERROR|WARNING)"' ~/factory-data/worker.log | tail -50
```

Что происходило с одним постом:

```bash
grep '"post_id": 7' ~/factory-data/worker.log
```

### Поставить систему на паузу, ничего не удаляя

```bash
uv run factory project pause demo
```

Новые посты создаваться не будут, существующие перестанут двигаться. Всё
остаётся на месте. Вернуть в работу:

```bash
uv run factory project resume demo
```

## Контент

### Добавить темы в очередь

Создай текстовый файл — одна тема на строку — и загрузи:

```bash
uv run factory topics import demo ~/новые-темы.txt
```

Повторы и пустые строки пропускаются, поэтому можно загружать один и тот же
файл несколько раз без вреда.

### Посмотреть, сколько тем осталось

```bash
uv run factory topics list demo
```

```
свободных: 14, в работе: 6, использованных: 30
```

Когда свободные закончатся, система перестанет создавать новые посты и напишет
об этом в логах. Держи запас хотя бы на две недели.

**В боте подробнее** — команда `/topics` показывает не числа, а три списка:

- **в запасе** — по очереди, в которой их возьмут;
- **в работе** — с тем, на каком шаге пост: пишется текст, ждёт вашего решения,
  одобрен и ждёт слота, сломался;
- **отработано** — свежие сверху, со ссылкой на вышедший пост.

Длинные списки обрезаются и говорят, сколько ещё не поместилось.

### Посмотреть конкретный пост целиком

```bash
uv run factory post show 7
```

### Отменить одобренный, но ещё не опубликованный пост

```bash
uv run factory post reject 7 --reason trash
```

Пост уходит в мусор, а его тема возвращается в очередь и будет использована
заново — с другим текстом и другими картинками.

Причины: `text` — не понравился текст, `images` — не понравились картинки,
`trash` — не понравилось всё.

Уже опубликованный пост отменить нельзя: он виден подписчикам, и пометка в базе
его оттуда не уберёт. Удалять надо в самой группе ВКонтакте.

### Обновить ключ загрузки ВК

**Делать раз в сутки.** Ключ, которым система загружает картинки, живёт 24 часа.
Когда он истечёт, посты остановятся на шаге картинок с ошибкой 5.

Признак в логах:

```
"msg": "шаг не удался, попробуем позже", "state": "approved"
```

и в тексте ошибки — `ВКонтакте отказал в вызове photos.getWallUploadServer: ошибка 5`.

#### Через бота (обычный способ)

Бот пришлёт ссылку, по которой выдаётся **одноразовый код** — не готовый ключ.
Разница важная: ключ ВК привязывает к адресу того, кто его получил, а код ни к
чему не привязан. Ключ по коду выписывает себе сама система, на свой адрес.

**Поэтому обновлять можно откуда угодно** — из отпуска, с телефона, под VPN.


Ничего делать заранее не нужно. Когда ключ истечёт, бот сам напишет вам в
Telegram: объяснит, что случилось, и приложит ссылку.

1. Открыть ссылку из сообщения, нажать «Разрешить».
2. Откроется пустая белая страница. Скопировать из адресной строки браузера
   **весь адрес целиком** — вырезать ничего не надо.
3. Прислать его боту одним сообщением.

Бот вытащит ключ, сохранит его, **удалит ваше сообщение** (ключ даёт доступ к
сообществу, и висеть в переписке ему незачем) и подтвердит. Публикация
продолжится сама в ближайшую минуту, перезапускать ничего не нужно.

Если ключ не подошёл, бот скажет об этом и оставит старый — молча испортить
рабочую настройку он не может.

**Пришло «ключ выписан на другой адрес»?** Значит в конфиге нет
`vk.app_secret_env`, и работает старая схема с готовым ключом. Тогда ссылку
надо открывать без VPN, с той же сети, где стоит система. Либо добавить
защищённый ключ приложения и перейти на схему с кодом.

#### Руками (если бот не работает)

**Шаг 1.** Открой в браузере эту ссылку и нажми «Разрешить»:

```
https://oauth.vk.com/authorize?client_id=54733282&display=page&redirect_uri=https%3A%2F%2Foauth.vk.com%2Fblank.html&scope=photos&response_type=token&v=5.199
```

**Шаг 2.** Откроется пустая белая страница. Токен — в адресной строке, между
`access_token=` и `&expires_in`. Скопируй его.

**Шаг 3.** Замени строку в файле секретов:

```bash
sed -i '' '/^VK_UPLOAD_TOKEN=/d' ~/factory-data/.env
printf 'VK_UPLOAD_TOKEN=СЮДА_ТОКЕН\n' >> ~/factory-data/.env
chmod 600 ~/factory-data/.env
```

**Шаг 4.** Проверь и сдвинь застрявшие посты:

```bash
uv run factory doctor
uv run factory run --once
```

Перезапускать воркер не нужно: файл секретов читается при каждом проходе.

Почему так неудобно: ВК отменил право `offline`, которое делало ключ бессрочным.
Проверены все три способа получения ключа — сутки во всех. Подробности и что
именно проверялось — в `docs/ВК-как-это-работает.md`.

### Поменять модель, которая пишет тексты

В `projects/<slug>/config.yaml`, раздел `llm`:

```yaml
llm:
  model: "deepseek/deepseek-v3.2"
  price_input_per_1m: 22.5
  price_output_per_1m: 33.4
```

Цены — за миллион токенов, в той валюте, что стоит в `llm.currency` (по
умолчанию рубли). Их надо менять вместе с моделью, иначе отчёт о тратах будет
врать. Список моделей и цен — в личном кабинете RouterAI.

Что стоит знать перед сменой:

- **не бери модель с рассуждениями** без запаса по `max_tokens`. Такие модели
  тратят лимит на размышления и при тесном бюджете возвращают пустой ответ.
  Признак в логе: «Модель вернула пустой ответ»;
- **дороже не всегда лучше.** Проверено: на текстах для сообщества разница между
  моделью за 8 рублей в месяц и за 135 заметна, но не в разы.

После правки перезапускать ничего не нужно — конфиг читается каждый проход.

### Поменять модель фактчека

Это **отдельная** модель, и в этом весь смысл:

```yaml
llm:
  factcheck_model: "perplexity/sonar"
  factcheck_web_search: true
  factcheck_price_input_per_1m: 107.8
  factcheck_price_output_per_1m: 107.8
```

**Не ставь сюда модель без веб-поиска.** Проверено на живом примере: модель без
доступа к источникам одобрила текст, где штраф был завышен в сто раз, и
сослалась на несуществующий пункт приказа. Проверка, которая уверенно
подтверждает выдумку, хуже её отсутствия.

Если модель искать не умеет — поставь `factcheck_web_search: false` и
`content.factcheck: light`. Понизить до `light` можно и при модели с поиском:
режим из конфига главнее, проверка станет дешевле и честно об этом напишет. Тогда проверяются только внутренние противоречия, а
к заметкам приписывается «факты не подтверждены». Система откажется запускаться,
если `strict` стоит вместе с моделью без поиска.

### Посмотреть, сколько потрачено

```bash
uv run factory stats vk_demo --days 30
```

Показывает потраченное за период и разбивку постов по состояниям. Порядок
величины для ориентира: **14 копеек за пост** без картинок и **6,7 ₽** с
картинками — то есть картинки дороже текста примерно в сорок раз. При двух
постах в сутки это около 400 ₽ в месяц, при шести — 1200 ₽.

### Включить настоящие картинки

В `projects/<slug>/config.yaml`, раздел `image`:

```yaml
image:
  provider: openai_compatible
  api_key_env: LLM_API_KEY
  base_url_env: LLM_BASE_URL
  model: "black-forest-labs/flux.2-klein-4b"
  price_per_image: 1.68
```

Имя модели обязательно с организацией впереди — без неё ответ «Model not found».
Ключ и адрес те же, что у текстов: второй счёт заводить не нужно.

Прежде чем включать, подними два числа:

- **месячный лимит ключа** на routerai.ru (см. ниже) — картинки съедают его
  в сорок раз быстрее текстов;
- **`limits.max_cost_per_post`** в конфиге проекта. При 0.40 первый же пост
  остановится на обложке. Разумное значение с картинками — 12.

### Поменять внешность персонажа

Два поля, оба в разделе `image`:

```yaml
  character: >-
    woman, 27 years old, slim athletic build, shoulder-length dark brown hair,
    green eyes, small silver septum piercing
  reference: character/canon.png
  supports_reference: true
```

`character` — приметы по-английски, дописываются в начало каждого промпта.
`reference` — эталонный портрет внутри каталога проекта, уходит образцом.

Что держится и что нет (проверено на четырёх сценах):

| Признак | Держится |
|---------|----------|
| лицо, стрижка, цвет глаз | да |
| пирсинг, серьги | да |
| наличие татуировки | да |
| **рисунок** татуировки, на какой руке | нет |
| телосложение | приблизительно |

Отсюда правило: **не пиши в приметы то, что не держится.** Подробная татуировка
в карточке — это обещание постоянства, которого не будет, и разницу заметите вы,
а не система.

Новый эталонный портрет проще всего получить так же, как первый: сгенерировать
портрет в полный рост на сером фоне по той же карточке примет и положить файл в
`projects/<slug>/character/`. После замены портрета старые посты не изменятся —
персонаж поменяется со следующего.

`supports_reference` нельзя ставить на глазок. Проверено живьём:
`gemini-2.5-flash-image` принимает образец, отвечает успехом, берёт деньги — и
рисует другого человека. Поставить ей `true` значит платить за узнаваемость и не
получать её, без единой ошибки в логе.

### Поменять вид обложки

Всё оформление — в `projects/<slug>/templates/red_frame.json`, код при этом не
трогается. Что чаще всего хочется поправить:

| Поле | Что делает |
|------|------------|
| `title.size_max` | потолок кегля заголовка. Больше — крупнее буквы и выше белая плашка |
| `plate.height` | **потолок** высоты плашки, а не её высота |
| `plate.fit_to_text` | плашка сжимается по тексту: короткий заголовок не закрывает картинку зря |
| `plate.color`, `frame.color` | цвета плашки и рамки, в записи `#RRGGBB` |
| `title.accent_lines` | сколько первых строк красить акцентным цветом |

Заголовок всегда рисуется **локально**, шрифтом из `assets/fonts/`. Просить
нейросеть написать русский текст на картинке нельзя: она рисует правдоподобную
бессмыслицу, а заголовок — единственное, что человек читает до того, как решит
читать пост.

Сколько места займёт плашка, зависит от длины заголовка. При `size_max: 78` и
включённом `fit_to_text` короткий заголовок в одну строку берёт около 11%
высоты, длинный в две — около 18%. Если хочется крупнее — поднимайте
`size_max`, плашка вырастет следом сама.

Проверить, как выйдет, не тратя денег на генерацию: собрать обложку поверх любой
готовой картинки.

```bash
uv run python -c "
from pathlib import Path
from factory.compose import cover
Path('/tmp/proba.png').write_bytes(
    cover.render(Path('ЛЮБАЯ_КАРТИНКА.png').read_bytes(),
                 'Ваш заголовок',
                 Path('projects/vk_demo/templates/red_frame.json')))
"
open /tmp/proba.png
```

### Перевыпустить ключ сообщества ВК

Нужно, если ключ куда-то утёк: попал в переписку, в скриншот, в чужой терминал.
В отличие от ключа загрузки, он не истекает сам — то есть будет работать у того,
кто его увидел, пока вы его не отзовёте.

1. Открыть vk.com → ваше сообщество → «Управление» → «Работа с API»;
2. На вкладке «Ключи доступа» удалить старый ключ и создать новый с теми же
   правами (**Управление**, **Стена**);
3. Вписать его в файл секретов — на малине:

```bash
ssh tequilex@192.168.3.19
sed -i '/^VK_TOKEN_GROUP=/d' ~/factory/data/.env
printf 'VK_TOKEN_GROUP=НОВЫЙ_КЛЮЧ\n' >> ~/factory/data/.env
cd ~/factory && docker compose restart worker
```

И то же самое в `data-local/.env`, если гоняете опыты локально.

Старые посты от этого не пострадают: ключ нужен только для новых публикаций.

### Поднять месячный лимит ключа RouterAI

Признак: в Telegram пришло «⛔️ Работа встала: провайдер отказывает» со словами
про spending limit, а посты не двигаются.

1. Зайти на routerai.ru в личный кабинет;
2. Открыть настройки ключа (тот, что в `LLM_API_KEY`);
3. Поднять месячный лимит расходов.

Перезапускать ничего не нужно: посты стоят в ожидании и пойдут дальше сами,
а тревога снимется на первом же удавшемся шаге. Ничего не потеряно — лимит
провайдера не ошибка, а отказ, который снимает человек.

### Поменять расписание публикаций

Открой `projects/demo/config.yaml` и поправь:

```yaml
vk:
  schedule: ["19:30", "21:00"]
  timezone: "Europe/Moscow"
```

В каждый слот уходит **один** пост. Слотов должно быть не меньше, чем
`limits.posts_per_day`, иначе часть постов не выйдет — при боевом публикаторе
система откажется запускаться с таким конфигом и скажет, сколько слотов нужно.

У каждого слота есть окно в час: пост, не ушедший ровно в 19:30, выйдет в
течение часа после. Окно переходит через полночь корректно — слот 23:30 живёт
до 00:30.

После правки перезапусти воркер — конфиг читается при каждом проходе, но
перезапуск гарантирует, что применилось.

### Поменять стиль текстов

Правятся три файла, код трогать не нужно:

| Файл | Что задаёт |
|------|------------|
| `projects/demo/prompts/voice.md` | кто пишет и как: тон, запреты, чем заканчивать |
| `projects/demo/prompts/examples/*.md` | примеры постов для подражания |
| `projects/demo/config.yaml`, раздел `content` | структура и длина |

**Важно:** в файлах промптов не должно быть пояснений для человека — нейросеть
читает их дословно и примет за часть задания. Всё, что надо объяснить людям,
пиши в `projects/demo/README.md`.

Чтобы временно выключить пример, переименуй его в `.md.off` — удалять не нужно.

Изменения подействуют на новые посты. Уже написанные не переписываются.

### Поменять, сколько постов в сутки

`projects/demo/config.yaml`:

```yaml
limits:
  posts_per_day: 2      # сколько публикуется в сутки
  queue_buffer: 6       # сколько постов держать в работе; ставь posts_per_day × 3
```

`queue_buffer` — запас готовых постов. При значении 6 и двух публикациях в сутки
запас на три дня: можно не заходить в Telegram на выходных.

## Новая группа

Ожидаемое время — полчаса. Полностью работает начиная с Этапа 2.

1. **Скопируй учебный проект под новым именем.** Имя — латиницей, без пробелов.

   ```bash
   cp -r projects/demo projects/moya_gruppa
   ```

2. **Открой `projects/moya_gruppa/config.yaml` и поменяй:**
   - `slug: moya_gruppa` — должно совпадать с именем каталога, иначе запуск
     откажется работать (это защита от рассинхрона);
   - `vk.group_id` — номер твоей группы;
   - `vk.token_env: VK_TOKEN_MOYA_GRUPPA` — имя переменной, **не сам токен**;
   - `persona.name` — как зовут персонажа;
   - `vk.schedule` — когда публиковать.

3. **Положи токен в файл секретов:**

   ```bash
   echo 'VK_TOKEN_MOYA_GRUPPA=vk1.a.НАСТОЯЩИЙ_ТОКЕН' >> ~/factory-data/.env
   chmod 600 ~/factory-data/.env
   ```

4. **Перепиши промпты** — `prompts/voice.md` и файлы в `prompts/examples/` — под

5. **Подключи проект и загрузи темы:**

   ```bash
   uv run factory project add moya_gruppa
   uv run factory topics import moya_gruppa ~/темы-новой-группы.txt
   ```

6. **Проверь:**

   ```bash
   uv run factory doctor
   ```

7. **Перезапусти воркер.**

Учебный проект `demo` можно оставить — он ничего не публикует наружу.

## Когда сломалось

### Посты застряли и не двигаются

```bash
uv run factory doctor
uv run factory post list demo
```

Смотри, что написано справа от состояния поста — там последняя ошибка.

Три частые причины:

| Что видно | Что делать |
|-----------|------------|
| `тик не отрабатывал N минут` | воркер не запущен — запусти его |
| `сейчас идёт тик (или осталась блокировка после сбоя)` больше получаса | `uv run factory unlock` |
| `закончились темы` | загрузи новые темы |

Если пост стоит с ошибкой:

```bash
uv run factory post show 7        # прочитать ошибку целиком
uv run factory post retry 7       # попробовать ещё раз прямо сейчас
```

### Как перезапустить один конкретный пост

```bash
uv run factory post retry 7
```

Сбрасывает счётчик ошибок и убирает паузу. Пост поедет со следующего прохода.

Если пост в состоянии `failed`, он вернётся в самое начало и будет написан
заново с нуля.

### Как посмотреть, на что уходят деньги

```bash
uv run factory stats demo
uv run factory post show 7        # стоимость одного поста
```

На Этапе 1 везде ноль: провайдеры — заглушки.

### Закончились деньги на API

*(актуально с Этапа 3)* Посты начнут копиться в состоянии, на котором обрывается
цепочка, а в логах пойдут ошибки с кодом 401 или 402. Пополни баланс и:

```bash
uv run factory post retry 7
```

Чтобы не тратить лишнего, пока разбираешься:

```bash
uv run factory project pause demo
```

### ВК вернул ошибку публикации

*(актуально с Этапа 2)* Смотри полный текст ошибки:

```bash
uv run factory post show 7
```

### Пришло «воркер молчит»

Значит бот жив, а процесс, который делает работу, — нет. Кнопки будут
срабатывать, но посты не поедут.

```bash
pgrep -f "factory run" || echo "воркер не работает"
tail -50 ~/factory-data/worker.log
```

Не работает — запустить (см. «Запустить всё»). Падает сразу после запуска —
причина в последних строках лога, чаще всего битый конфиг или недоступная сеть.

Когда воркер вернётся, бот пришлёт «воркер вернулся»: молча гасить тревогу
нельзя — иначе непонятно, починилось или просто перестало сообщать.

Порог молчания — 10 минут, меняется переменной `FACTORY_HEARTBEAT_STALE_SEC`.

### Бот не отвечает в Telegram

**Сначала проверь, что он вообще запущен:**

```bash
pgrep -f "factory bot" || echo "бот не работает"
```

Не работает — запустить (см. «Запустить всё»). Работает, а кнопки молчат —
смотреть лог:

```bash
tail -50 ~/factory-data/bot.log
```

| Что в логе | Что это значит | Что делать |
|------------|----------------|------------|
| `Unauthorized` | токен бота неверен или бот удалён у @BotFather | перевыпустить токен, заменить `TELEGRAM_BOT_TOKEN` в файле секретов |
| `bot can't initiate conversation` | вы не писали боту `/start` | открыть бота в Telegram и отправить `/start` |
| `chat not found` | неверный `telegram.chat_id` в конфиге | узнать своё число у @userinfobot, вписать в конфиг |
| `нажатие от постороннего` | кнопку нажал не тот, кто в `telegram.reviewers` | так и задумано; чтобы разрешить — добавить его число в список |
| `Start polling` и тишина | бот жив, но сообщений нет | проверить, что воркер работает: посты отправляет он, а не бот |

**Кнопки нажимаются, но ничего не происходит.** Значит, не работает воркер:
бот меняет состояние поста, а работу по нему делает воркер. Проверить:

```bash
pgrep -f "factory run" || echo "воркер не работает"
```

**Посты не приходят вовсе.** Проверить, что проект в режиме ревью:

```bash
grep -A1 "^review:" ~/Desktop/pipline/projects/vk_demo/config.yaml
```

Должно быть `mode: telegram`. При `mode: auto` посты публикуются без вопросов —
это отдельный режим, а не поломка.

### Посмотреть, что в запасе и что уже сделано

```
/topics
```

Три списка:

- **в запасе** — по очереди, в которой их возьмут;
- **в работе** — с тем, на каком шаге пост: пишется текст, ждёт решения,
  одобрен и ждёт слота, сломался;
- **отработано** — свежие сверху, со ссылкой на вышедший пост.

Длинные списки обрезаются и говорят, сколько ещё не поместилось.

### Добавить темы с телефона

Прислать боту сообщение со списком — по теме в строке. Он покажет, что понял,
и спросит подтверждение. После подтверждения темы попадают в очередь, повторы
и пустые строки пропускаются.

Это то же самое, что `factory topics import`, только из переписки.

### Выбросить пост или тему

Кнопка «🗑 В мусор» ничего не выбрасывает сразу — она спрашивает:

- **«Только этот пост»** — пост в отказ, тема возвращается в очередь **в
  конец**. Система напишет по ней снова, но не сейчас, а когда дойдёт очередь;
- **«Пост и тему»** — тема закрывается насовсем.

Второе нужно, когда плоха сама тема: иначе система будет писать по ней посты
бесконечно, и каждый придётся выбрасывать заново.

Вернуть закрытую тему можно, прислав её боту заново обычным списком.

### Отменить одобрение, пока пост не вышел

Под одобренным постом остаётся кнопка **«↩️ Отменить публикацию»**. Нажмите —
вернутся все пять решений, ничего не перегенерируется.

Пост уже вышел — отменить нельзя: удалять записи в группе система не умеет и не
должна. Кнопка в этом случае объяснит, что удалять надо в самой группе.

### Публиковать сразу или по расписанию

```
/schedule      — посмотреть, как сейчас
/schedule_off  — публиковать сразу после одобрения
/schedule_on   — вернуть ожидание слота
```

Дневной лимит `limits.posts_per_day` действует в обоих режимах: он про
количество, а не про время. Одобрили больше, чем лимит, — остаток уедет завтра.

Переменная `FACTORY_IGNORE_SCHEDULE` по-прежнему главнее: её задаёт тот, кто
запускает процесс, и переключатель в боте её не отменяет.

### Остановить и продолжить выпуск

```
/pause    — остановить
/resume   — продолжить
```

Пауза останавливает проект целиком: новые посты не готовятся, публикаций нет,
уже одобренные ждут. Из командной строки то же самое:

```bash
uv run factory project pause vk_demo
uv run factory project resume vk_demo
```

### Вернуться к предыдущему варианту поста

Каждое нажатие «Текст заново» или «Другие сцены» создаёт новый вариант и
присылает его отдельным сообщением. Прежние никуда не деваются.

Чтобы опубликовать старый — пролистайте переписку вверх до нужного варианта
(в заголовке написано, какой он по счёту) и нажмите под ним **«Опубликовать
этот»**. Уйдёт именно этот текст с этими картинками.

Посмотреть все варианты поста из командной строки:

```bash
uv run factory post show 12
```

Он печатает список вариантов с номерами и пометкой, какой сейчас текущий.

### Поправить текст поста, не переписывая его целиком

Ответьте боту на сообщение с постом — тем, под которым кнопки, — своим
вариантом текста. Он заменит и вернёт пост на просмотр.

Чтобы поменять и заголовок, пришлите его первой строкой, дальше пустую строку,
дальше текст. Заголовок идёт на обложку, поэтому она пересоберётся, и картинки
придут заново.

Ответ на любое другое сообщение бот не поймёт и скажет об этом.

### Сменить того, кто одобряет посты

В `projects/<slug>/config.yaml`:

```yaml
telegram:
  chat_id: 123456789        # куда приходят посты
  reviewers: [123456789]    # кто может нажимать кнопки
```

Своё число человек узнаёт, написав боту @userinfobot. Список можно расширить —
тогда нажимать смогут все перечисленные. **Пустым он быть не может:** бот
находится в Telegram обычным поиском, и без списка кнопка «Опубликовать» в вашу
группу доступна каждому, кто на бота наткнулся.

Новому человеку надо самому отправить боту `/start` — Telegram запрещает боту
писать первым.

### Какие тревоги присылает бот

| Сообщение | Когда | Что делать |
|-----------|-------|------------|
| ключ загрузки ВК истёк | публикация упёрлась в ошибку 5 | прислать боту адрес по ссылке из сообщения |
| скоро публиковать нечего | свободных тем нет и постов в работе меньше, чем выпускается за сутки | `factory topics import <проект> темы.txt` |
| пост ждёт больше суток | висит на одном шаге 24 часа | посмотреть `factory post show N`; если это ревью — нажать кнопку |
| пост сломался окончательно | исчерпаны пять попыток | причина в сообщении; починив, `factory post retry N` |
| ⛔️ работа встала: провайдер отказывает | исчерпан месячный лимит ключа или отозван доступ | поднять лимит в кабинете провайдера, см. выше |
| 💸 пост вышел дороже потолка | сумма вызовов перешла `limits.max_cost_per_post` | поднять потолок в конфиге или выбросить пост |

Каждая тревога приходит **один раз**. Повторится, только если причина исчезла и
появилась снова. Тревоги на «несколько постов ждут решения» нет намеренно: это
нормальная работа, а не авария.

## Разработка локально

Порядок такой: пишете и проверяете на ноутбуке, заливаете в репозиторий,
малина забирает и пересобирает.

### Опыты с внешностью, стилем и темами

Отдельная площадка на ноутбуке: своя база, свои темы, свой проект `vk_local`,
но **публикация в ту же тестовую группу**. Пересборка образа не нужна — код
запускается прямо из исходников, правка видна на следующем проходе.

Флоу такой же, как в бою, **включая кнопки в Telegram**: смысл опытов в том,
чтобы увидеть боевое поведение, а не его упрощённую версию. Отличий два, и оба
вынужденные — свой бот и свой слаг проекта.

Расписание при этом обычно не ждут: запуск с `FACTORY_IGNORE_SCHEDULE=1`, иначе
своя же правка увидится через несколько часов. Убрать переменную, если надо
проверить и расписание тоже.

#### Первым делом: остановить малину

Обязательно останавливается **воркер**: защита от дублей живёт в базе, а базы
разные — два воркера на одну группу друг о друге не знают.

**Бота на малине тоже стоит остановить.** Он ничего не публикует, но пишет в тот
же чат: во-первых, вы получите два бота в одной переписке и перепутаете, чьи
кнопки нажимаете; во-вторых, через десять минут он пожалуется «воркер молчит» —
и будет прав, но вам это сейчас не нужно.

```bash
ssh tequilex@192.168.3.19 "cd ~/factory && docker compose stop worker bot"
```

Вернуть малину в работу после опытов:

```bash
ssh tequilex@192.168.3.19 "cd ~/factory && docker compose start worker bot"
```

#### Отдельный бот для опытов

Нужен обязательно. Telegram не разрешает двум процессам опрашивать один токен:
они перехватывают нажатия друг у друга, и часть решений пропадает **без единой
ошибки** — просто нажали и ничего не произошло.

1. Написать [@BotFather](https://t.me/BotFather) команду `/newbot`;
2. Придумать имя, например «Фабрика опыты»;
3. Полученный токен вписать в `data-local/.env` в строку
   `TELEGRAM_BOT_TOKEN_LOCAL=`;
4. Найти нового бота поиском и отправить ему `/start` — Telegram запрещает боту
   писать первым.

Боевой токен сюда класть нельзя: это ровно тот запрет, что описан выше.

#### Запуск

```bash
export FACTORY_DATA_DIR=$(pwd)/data-local
export FACTORY_PROJECTS_DIR=$(pwd)/projects-local
export FACTORY_IGNORE_SCHEDULE=1
export FACTORY_TICK_INTERVAL_SEC=15

uv run factory project add vk_local          # только в первый раз
uv run factory topics import vk_local ~/темы.txt
uv run factory run --loop
```

Во **втором терминале** — бот, с теми же тремя `export`:

```bash
uv run factory bot
```

Процессов два, и нужны оба: воркер готовит посты и присылает их, бот принимает
нажатия. Работает только воркер — посты приходят, кнопки молчат.

Первый запуск сам создаст базу в `data-local/` и применит миграции. Проект надо
**подключить к базе** отдельной командой: конфиг на диске и запись в базе — две
разные вещи, и без второй воркер проект просто не увидит.

Если после `Ctrl+C` следующий запуск говорит «Тик пропущен: уже работает другой
процесс» — осталась блокировка от прерванного прохода:

```bash
uv run factory unlock
```

#### Что где править

| Хочу попробовать | Файл в `projects-local/vk_local/` |
|---|---|
| другую внешность | `config.yaml`, поле `image.character` |
| другой эталонный портрет | положить свой `character/canon.png` |
| другой стиль съёмки | `config.yaml`, поле `image.scene_style` |
| другой характер текстов | `prompts/voice.md` |
| другие образцы стиля | `prompts/examples/*.md` |
| другой вид обложки | `templates/red_frame.json` |

Боевой конфиг лежит в другом каталоге и от этих правок не меняется. Когда
что-то понравилось — перенести руками нужные строки в `projects/vk_demo/`.

#### Подобрать внешность, не гоняя пост

Целый пост стоит около 6.7 ₽ и минут пять. Чтобы крутить приметы быстро, есть
скрипт на одну картинку — тот же провайдер, та же модель, тот же эталон:

```bash
uv run python scripts/preview_character.py \
    --project vk_local \
    --scene "checking the engine oil, hood open, daylight" \
    --out ~/Desktop/проба.png
```

Полезные ключи:

| Ключ | Зачем |
|---|---|
| `--character "..."` | другие приметы, не трогая конфиг |
| `--style "..."` | другой стиль съёмки |
| `--title "Заголовок"` | заодно собрать обложку и посмотреть, не закрывает ли плашка лицо |
| `--seed 42` | повторить тот же кадр |
| `--no-reference` | без эталона — видно, что держится одними словами |

Одна картинка — 1.68 ₽.

#### Ключ загрузки ВК

Он живёт сутки и обновляется через бота, то есть попадает в файл секретов **на
малине**. Локальная копия про это не знает. Забрать свежий:

```bash
TOKEN=$(ssh tequilex@192.168.3.19 "grep '^VK_UPLOAD_TOKEN=' ~/factory/data/.env")
sed -i '' '/^VK_UPLOAD_TOKEN=/d' data-local/.env
echo "$TOKEN" >> data-local/.env
```

Признак, что пора: в логе `ВКонтакте отказал ... ошибка 5`.

### Быстрый круг: правка и тесты

Для работы над кодом Docker не нужен и только замедляет:

```bash
uv run pytest                    # все тесты
uv run pytest tests/test_edits.py -v
uv run python scripts/mutation_check.py scripts/mutations/decisions.json
```

### Проверить, что работает как на малине

Тот же образ, та же сборка, но своя база и заглушки вместо настоящих сервисов:

```bash
docker compose -f docker-compose.local.yml up -d --build
docker compose -f docker-compose.local.yml logs -f
docker compose -f docker-compose.local.yml down
```

Локально подключается `projects/demo` — там все провайдеры заглушки, наружу
система не ходит и в группу ничего не публикует.

### Три правила, чтобы не сломать боевую

1. **Своя база.** Локальный стек работает с `./data-local`, боевой — с
   `./data`. Не смешивать: посты разойдутся, и понять, какой настоящий, будет
   нельзя.
2. **Никогда два воркера на одну группу.** Защита от дублей живёт в базе, а
   базы разные — она не сработает, и в группу уедут два поста вместо одного.
3. **Никогда два бота на один токен.** Telegram не разрешает двум процессам
   опрашивать один токен: они перехватывают нажатия друг у друга, и вы видите
   случайные пропажи. Нужен бот локально — заведите **второго** у @BotFather и
   пропишите его токен в `data-local/.env`.

### Что НЕ едет через git

Секреты (`data/.env`) и боевые проекты (`projects/vk_demo/`) в репозитории не
лежат — он публичный. Они переносятся вручную:

```bash
scp -r projects/vk_demo tequilex@192.168.3.19:~/factory/projects/
scp ~/factory-data/.env tequilex@192.168.3.19:~/factory/data/.env
ssh tequilex@192.168.3.19 "chmod 600 ~/factory/data/.env"
```

**Конфиг подкладывать ПОСЛЕ того, как поднялся новый образ, а не до.** Порядок
здесь не вкусовщина. Проверка конфига строгая: незнакомое поле — ошибка, и
старый код отвергает конфиг, написанный для нового. Проект не загружается
целиком, а вместе с ним пропадает и список проверяющих — то есть кнопки
перестают работать у всех, включая вас.

Правильно так:

```bash
ssh tequilex@192.168.3.19 "cd ~/factory && git pull && docker compose up -d --build"
# дождаться, пока docker compose ps покажет «Up N seconds»
scp projects/vk_demo/config.yaml tequilex@192.168.3.19:~/factory/projects/vk_demo/
```

Если всё-таки подложили раньше — ничего страшного и чинить руками не нужно:
как только новый образ поднимется, конфиг прочитается сам.

## Обслуживание

### Сделать бэкап руками

```bash
mkdir -p ~/factory-data/backups
uv run python -c "
import sqlite3, pathlib, datetime
target = pathlib.Path.home() / 'factory-data' / 'backups' / f\"factory-{datetime.date.today()}.db\"
conn = sqlite3.connect(pathlib.Path.home() / 'factory-data' / 'factory.db')
conn.execute('VACUUM INTO ?', (str(target),))
conn.close()
print('готово:', target)
"
```

`VACUUM INTO` делает целостную копию даже на работающей системе — останавливать
воркер не нужно.

### Восстановиться из бэкапа

```bash
kill "$(cat ~/factory-data/worker.pid)"
while pgrep -f "factory run --loop" > /dev/null; do sleep 1; done

rm -f ~/factory-data/factory.db ~/factory-data/factory.db-wal ~/factory-data/factory.db-shm
cp ~/factory-data/backups/factory-2026-08-23.db ~/factory-data/factory.db

uv run factory doctor
```

Два неочевидных шага, без которых восстановление испортит базу:

- **дождаться выхода воркера.** `kill` только просит остановиться; копирование
  поверх работающей базы даст мешанину;
- **удалить файлы `-wal` и `-shm`.** Это журнал старой базы. Если оставить его
  рядом с восстановленным файлом, SQLite попытается доиграть в него чужие
  изменения.

### Перенести всё на другой сервер

Всё состояние системы лежит в одном каталоге. Переезд — три шага:

1. скопировать каталог `~/factory-data` целиком;
2. скопировать сам проект (или взять из репозитория);
3. запустить воркер на новом месте.

Ничего, кроме этого каталога, переносить не нужно — это проверяется тем, что
все пути в системе задаются переменными окружения.

### Обновиться до новой версии

```bash
kill "$(cat ~/factory-data/worker.pid)"
git pull
uv sync
uv run factory doctor        # применит миграции базы, если они есть
```

### Откатиться на предыдущую версию

Посмотри список версий и скопируй номер нужной из первой колонки:

```bash
git log --oneline | head -20
```

```
a653bdc fix: убрана тематика из stub-провайдера LLM
a8f11ca docs: README, RUNBOOK, TROUBLESHOOTING
9d5b203 test: возобновляемость после краша
```

Дальше подставь этот номер:

```bash
git checkout a8f11ca
uv sync
uv run factory doctor
```

Вернуться на последнюю версию: `git checkout main`.

Если новая версия успела изменить схему базы, восстанови её из бэкапа — старый
код может не понять новую схему.
