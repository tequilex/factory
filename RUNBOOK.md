# RUNBOOK — рецепты на каждый день

Сборник «хочу сделать X → выполни это». Команды можно копировать целиком.

Во всех рецептах предполагается, что ты в каталоге проекта и выполнил:

```bash
export PATH="$HOME/.local/bin:$PATH"
export FACTORY_DATA_DIR=~/factory-data
export FACTORY_PROJECTS_DIR=$(pwd)/projects
```

Чтобы не повторять это каждый раз, добавь три строки в конец `~/.zshrc`.

> **Что доступно на Этапе 1.** Рецепты ниже работают уже сейчас. Разделы про
> Telegram, реальную публикацию и Docker появятся на этапах 5, 2 и 7 —
> они помечены как **позже**.

## Ежедневное

### Запустить всё

```bash
uv run factory run --loop
```

Работает, пока открыт терминал. Остановить — `Ctrl+C`: система доделает текущий
проход и остановится, ничего не потеряв.

Чтобы работало в фоне и не зависело от терминала:

```bash
nohup uv run factory run --loop > ~/factory-data/worker.log 2>&1 &
echo $! > ~/factory-data/worker.pid
```

### Остановить всё

```bash
kill "$(cat ~/factory-data/worker.pid)"
```

Обычная остановка, а не убийство: текущий проход доработает до конца.

Если процесс не откликается больше минуты:

```bash
kill -9 "$(cat ~/factory-data/worker.pid)"
uv run factory unlock
```

Второй командой снимается блокировка, оставшаяся от убитого процесса.

### Посмотреть, что происходит прямо сейчас

```bash
uv run factory doctor
```

Покажет: где база, когда последний раз отрабатывал воркер, сколько тем осталось
у каждого проекта, не идёт ли прямо сейчас проход.

```bash
uv run factory post list demo
```

Последние двадцать постов и их состояния.

### Посмотреть логи

Все за последнее время:

```bash
tail -n 200 ~/factory-data/worker.log
```

Следить вживую:

```bash
tail -f ~/factory-data/worker.log
```

Только ошибки и предупреждения:

```bash
grep -E '"level": "(ERROR|WARNING)"' ~/factory-data/worker.log | tail -50
```

Что происходило с одним постом:

```bash
grep '"post_id": 7' ~/factory-data/worker.log
```

### Поставить систему на паузу, ничего не удаляя

```bash
uv run factory project pause demo
```

Новые посты создаваться не будут, существующие перестанут двигаться. Всё
остаётся на месте. Вернуть в работу:

```bash
uv run factory project resume demo
```

## Контент

### Добавить темы в очередь

Создай текстовый файл — одна тема на строку — и загрузи:

```bash
uv run factory topics import demo ~/новые-темы.txt
```

Повторы и пустые строки пропускаются, поэтому можно загружать один и тот же
файл несколько раз без вреда.

### Посмотреть, сколько тем осталось

```bash
uv run factory topics list demo
```

```
свободных: 14, в работе: 6, использованных: 30
```

Когда свободные закончатся, система перестанет создавать новые посты и напишет
об этом в логах. Держи запас хотя бы на две недели.

### Посмотреть конкретный пост целиком

```bash
uv run factory post show 7
```

### Отменить одобренный, но ещё не опубликованный пост

```bash
uv run factory post reject 7 --reason trash
```

Пост уходит в мусор, а его тема возвращается в очередь и будет использована
заново — с другим текстом и другими картинками.

Причины: `text` — не понравился текст, `images` — не понравились картинки,
`trash` — не понравилось всё.

Уже опубликованный пост отменить нельзя: он виден подписчикам, и пометка в базе
его оттуда не уберёт. Удалять надо в самой группе ВКонтакте.

### Поменять расписание публикаций

Открой `projects/demo/config.yaml` и поправь:

```yaml
vk:
  schedule: ["19:30", "21:00"]
  timezone: "Europe/Moscow"
```

В каждый слот уходит **один** пост. Слотов должно быть не меньше, чем
`limits.posts_per_day`, иначе часть постов не выйдет.

После правки перезапусти воркер — конфиг читается при каждом проходе, но
перезапуск гарантирует, что применилось.

### Поменять стиль текстов

Правятся три файла, код трогать не нужно:

| Файл | Что задаёт |
|------|------------|
| `projects/demo/prompts/voice.md` | кто пишет и как: тон, запреты, чем заканчивать |
| `projects/demo/prompts/examples/*.md` | примеры постов для подражания |
| `projects/demo/config.yaml`, раздел `content` | структура и длина |

**Важно:** в файлах промптов не должно быть пояснений для человека — нейросеть
читает их дословно и примет за часть задания. Всё, что надо объяснить людям,
пиши в `projects/demo/README.md`.

Чтобы временно выключить пример, переименуй его в `.md.off` — удалять не нужно.

Изменения подействуют на новые посты. Уже написанные не переписываются.

### Поменять, сколько постов в сутки

`projects/demo/config.yaml`:

```yaml
limits:
  posts_per_day: 2      # сколько публикуется в сутки
  queue_buffer: 6       # сколько постов держать в работе; ставь posts_per_day × 3
```

`queue_buffer` — запас готовых постов. При значении 6 и двух публикациях в сутки
запас на три дня: можно не заходить в Telegram на выходных.

## Новая группа

Ожидаемое время — полчаса. Полностью работает начиная с Этапа 2.

1. **Скопируй учебный проект под новым именем.** Имя — латиницей, без пробелов.

   ```bash
   cp -r projects/demo projects/moya_gruppa
   ```

2. **Открой `projects/moya_gruppa/config.yaml` и поменяй:**
   - `slug: moya_gruppa` — должно совпадать с именем каталога, иначе запуск
     откажется работать (это защита от рассинхрона);
   - `vk.group_id` — номер твоей группы;
   - `vk.token_env: VK_TOKEN_MOYA_GRUPPA` — имя переменной, **не сам токен**;
   - `persona.name` — как зовут персонажа;
   - `vk.schedule` — когда публиковать.

3. **Положи токен в файл секретов:**

   ```bash
   echo 'VK_TOKEN_MOYA_GRUPPA=vk1.a.НАСТОЯЩИЙ_ТОКЕН' >> ~/factory-data/.env
   chmod 600 ~/factory-data/.env
   ```

4. **Перепиши промпты** — `prompts/voice.md` и файлы в `prompts/examples/` — под
   свою тематику. Учебные примеры про машины оставлять нельзя: нейросеть будет
   писать про машины.

5. **Подключи проект и загрузи темы:**

   ```bash
   uv run factory project add moya_gruppa
   uv run factory topics import moya_gruppa ~/темы-новой-группы.txt
   ```

6. **Проверь:**

   ```bash
   uv run factory doctor
   ```

7. **Перезапусти воркер.**

Учебный проект `demo` можно оставить — он ничего не публикует наружу.

## Когда сломалось

### Посты застряли и не двигаются

```bash
uv run factory doctor
uv run factory post list demo
```

Смотри, что написано справа от состояния поста — там последняя ошибка.

Три частые причины:

| Что видно | Что делать |
|-----------|------------|
| `тик не отрабатывал N минут` | воркер не запущен — запусти его |
| `сейчас идёт тик (или осталась блокировка после сбоя)` больше получаса | `uv run factory unlock` |
| `закончились темы` | загрузи новые темы |

Если пост стоит с ошибкой:

```bash
uv run factory post show 7        # прочитать ошибку целиком
uv run factory post retry 7       # попробовать ещё раз прямо сейчас
```

### Как перезапустить один конкретный пост

```bash
uv run factory post retry 7
```

Сбрасывает счётчик ошибок и убирает паузу. Пост поедет со следующего прохода.

Если пост в состоянии `failed`, он вернётся в самое начало и будет написан
заново с нуля.

### Как посмотреть, на что уходят деньги

```bash
uv run factory stats demo
uv run factory post show 7        # стоимость одного поста
```

На Этапе 1 везде ноль: провайдеры — заглушки.

### Закончились деньги на API

*(актуально с Этапа 3)* Посты начнут копиться в состоянии, на котором обрывается
цепочка, а в логах пойдут ошибки с кодом 401 или 402. Пополни баланс и:

```bash
uv run factory post retry 7
```

Чтобы не тратить лишнего, пока разбираешься:

```bash
uv run factory project pause demo
```

### ВК вернул ошибку публикации

*(актуально с Этапа 2)* Смотри полный текст ошибки:

```bash
uv run factory post show 7
```

### Бот не отвечает в Telegram

*(актуально с Этапа 5)*

## Обслуживание

### Сделать бэкап руками

```bash
mkdir -p ~/factory-data/backups
uv run python -c "
import sqlite3, pathlib, datetime
target = pathlib.Path.home() / 'factory-data' / 'backups' / f\"factory-{datetime.date.today()}.db\"
conn = sqlite3.connect(pathlib.Path.home() / 'factory-data' / 'factory.db')
conn.execute('VACUUM INTO ?', (str(target),))
conn.close()
print('готово:', target)
"
```

`VACUUM INTO` делает целостную копию даже на работающей системе — останавливать
воркер не нужно.

### Восстановиться из бэкапа

```bash
kill "$(cat ~/factory-data/worker.pid)"
cp ~/factory-data/backups/factory-2026-08-23.db ~/factory-data/factory.db
uv run factory doctor
```

### Перенести всё на другой сервер

Всё состояние системы лежит в одном каталоге. Переезд — три шага:

1. скопировать каталог `~/factory-data` целиком;
2. скопировать сам проект (или взять из репозитория);
3. запустить воркер на новом месте.

Ничего, кроме этого каталога, переносить не нужно — это проверяется тем, что
все пути в системе задаются переменными окружения.

### Обновиться до новой версии

```bash
kill "$(cat ~/factory-data/worker.pid)"
git pull
uv sync
uv run factory doctor        # применит миграции базы, если они есть
```

### Откатиться на предыдущую версию

```bash
git log --oneline | head -20     # найти нужный коммит
git checkout <номер-коммита>
uv sync
```

Если новая версия успела изменить схему базы, восстанови её из бэкапа — старый
код может не понять новую схему.
