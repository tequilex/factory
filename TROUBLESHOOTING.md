# TROUBLESHOOTING

Таблица «симптом → причина → чем проверить → как починить».

Пополняется по мере появления настоящих ошибок. Если столкнулся с чем-то, чего
здесь нет, — допиши строку, пока помнишь.

Во всех командах предполагается, что заданы `FACTORY_DATA_DIR` и
`FACTORY_PROJECTS_DIR` — см. [RUNBOOK.md](RUNBOOK.md).

---

## Запуск

| Симптом | Вероятная причина | Чем проверить | Как починить |
|---------|-------------------|---------------|--------------|
| `Каталог данных /data недоступен для записи` | значение по умолчанию рассчитано на контейнер | `echo $FACTORY_DATA_DIR` | `export FACTORY_DATA_DIR=~/factory-data` и добавить строку в `~/.zshrc` |
| `Конфиг проекта 'X' не найден` | не задан каталог с проектами или опечатка в имени | `ls projects/` | `export FACTORY_PROJECTS_DIR=$(pwd)/projects` |
| `factory: command not found` | `uv` не в `PATH` | `which uv` | `export PATH="$HOME/.local/bin:$PATH"` |
| `Проект 'X' не подключён к базе` | конфиг есть, но проект не зарегистрирован | `uv run factory project list` | `uv run factory project add X` |

## Конфигурация

| Симптом | Вероятная причина | Чем проверить | Как починить |
|---------|-------------------|---------------|--------------|
| `Конфиг проекта не прошёл проверку` + список полей | опечатка или пропущенное поле | текст ошибки называет файл и каждое поле | исправить перечисленное; образец — `projects/demo/config.yaml` |
| `неизвестное поле — скорее всего опечатка в названии` | лишняя или переименованная настройка | там же | сверить название с образцом |
| `Файл не читается как YAML` | сбитые отступы или пропущенное двоеточие | текст ошибки указывает строку | выравнять отступы (только пробелы, не табы) |
| `Имя проекта не совпадает с каталогом` | скопировали каталог, но не поменяли `slug` | `head -20 projects/X/config.yaml` | поставить `slug: X`, где X — имя каталога |
| `queue_buffer меньше posts_per_day` | система физически не выпустит столько постов | раздел `limits` | поставить `queue_buffer` ≈ `posts_per_day × 3` |
| `Не найден секрет для ...` | ключа нет в файле секретов | `grep ИМЯ_ПЕРЕМЕННОЙ ~/factory-data/.env` | добавить строку `ИМЯ=значение`, затем `chmod 600` |

## Работа воркера

| Симптом | Вероятная причина | Чем проверить | Как починить |
|---------|-------------------|---------------|--------------|
| Посты стоят, в логах пусто | воркер не запущен | `uv run factory doctor` → строка про последний тик | запустить `uv run factory run --loop` |
| `Тик пропущен: уже работает другой процесс` дольше получаса | блокировка осталась от убитого процесса | `uv run factory doctor` | `uv run factory unlock` |
| Посты доходят до `approved` и стоят | исчерпан дневной лимит или сейчас не время публикации | `uv run factory post show N` | это нормально; проверить `limits.posts_per_day` и `vk.schedule` |
| Пост в состоянии `failed` | пять неудачных попыток подряд | `uv run factory post show N` — там текст ошибки | устранить причину, затем `uv run factory post retry N` |
| Пост в `in_review` не двигается | ждёт кнопки в Telegram | `uv run factory post show N` | нажать кнопку; до Этапа 5 поставить `review.mode: auto` |
| `свободные темы закончились` | очередь тем пуста | `uv run factory topics list X` | `uv run factory topics import X файл.txt` |
| В логах WARNING про `FACTORY_IGNORE_SCHEDULE` | включён режим разработки | `echo $FACTORY_IGNORE_SCHEDULE` | `unset FACTORY_IGNORE_SCHEDULE` — иначе посты уйдут ночью |

## База данных

| Симптом | Вероятная причина | Чем проверить | Как починить |
|---------|-------------------|---------------|--------------|
| `database is locked` | два процесса пишут одновременно | `ps aux \| grep "factory run"` | оставить один воркер; лишние остановить |
| `Миграция NNN не применилась` | повреждён или изменён файл миграции | текст ошибки называет файл | база осталась на прежней версии и работает; восстановить файл из репозитория |
| `Миграция нарушила связи между таблицами` | миграция забыла перенести строки | текст ошибки называет таблицы | изменения отменены; исправить миграцию, см. `CLAUDE.md` → «Как менять схему базы» |
| Подозрение на порчу файла базы | внезапное отключение питания | `sqlite3 ~/factory-data/factory.db "PRAGMA integrity_check"` | если не `ok` — восстановить из бэкапа |

## Картинки и файлы

| Симптом | Вероятная причина | Чем проверить | Как починить |
|---------|-------------------|---------------|--------------|
| `ФАЙЛ ПРОПАЛ` в `post show` у неопубликованного поста | почистили временный каталог | `ls $FACTORY_TMP_DIR` | ничего не делать: следующий проход сгенерирует картинку заново |
| `удалена после публикации` | так и задумано | — | это не ошибка: после публикации файлы убираются, чтобы не копиться |
| Место на диске кончается | остались файлы недоведённых постов | `du -sh $FACTORY_TMP_DIR` | удалить каталоги постов, которые уже в `failed` или `rejected` |

## Публикация

*(актуально с Этапа 2)*

| Симптом | Вероятная причина | Чем проверить | Как починить |
|---------|-------------------|---------------|--------------|
| Один и тот же пост вышел дважды | процесс убили между отправкой и записью результата | сравнить `external_id` в базе с тем, что в группе | удалить лишний пост в группе руками; см. примечание ниже |

**Про дубли.** Система защищена от повторной публикации проверкой в базе, но есть
узкое окно: если процесс убить ровно между отправкой в ВК и записью результата,
следующий проход опубликует пост ещё раз. Окно закроется на Этапе 2, когда
появится настоящий публикатор с идентификатором операции (`guid` в ВК API).
До тех пор не убивай воркер командой `kill -9` во время окна публикации.

## Как собрать сведения для разбора

Если ничего из перечисленного не подошло, собери это перед тем, как просить
помощи:

```bash
uv run factory doctor
uv run factory post list
tail -n 100 ~/factory-data/worker.log
sqlite3 ~/factory-data/factory.db "PRAGMA user_version; PRAGMA integrity_check;"
```

В логах не бывает токенов и ключей — они вычищаются автоматически, поэтому вывод
можно показывать целиком.

## Публикация в ВК

| Симптом | Причина | Проверить | Что делать |
|---------|---------|-----------|------------|
| В логе `ошибка 5` на `photos.getWallUploadServer`, посты стоят в `approved` | Ключ загрузки истёк — он живёт 24 часа | `uv run factory post show <id>` → поле «последняя ошибка» | RUNBOOK → «Обновить ключ загрузки ВК» |
| В логе `ошибка 27` на загрузке картинок | Ключи перепутаны местами в конфиге | `grep token_env projects/<slug>/config.yaml` | `token_env` — ключ сообщества, `upload_token_env` — ключ пользователя. Не наоборот |
| В логе `ошибка 15` на `wall.post` | Публикация идёт ключом пользователя, а не сообщества | там же | Поменять местами значения в конфиге |
| В логе `ошибка 214` | Дневной лимит публикаций у самого сообщества либо ограничение ВК на группу | открыть группу в браузере | Подождать сутки; если повторяется — писать в поддержку ВК |
| `уборка оригиналов картинок недоступна` в логе | Так и есть: `photos.delete` запрещён приложениям этого типа | — | Ничего. Сообщение появляется один раз за запуск, на работу не влияет |
| `сервер загрузки вернул пустой ответ` | Известный сбой ВК, случается часто | — | Ничего, система повторяет сама с новым адресом |
| Пост опубликован, но в базе `approved` | Процесс убит между отправкой и записью | `uv run factory post show <id>` | Ничего: следующий тик пойдёт с тем же `guid`, и ВК вернёт уже созданный пост вместо второго |
| `Проектов: 0` в выводе тика | Проект не подключён или на паузе | `uv run factory project list` | `factory project add <slug>` либо `factory project resume <slug>` |

## Тексты и фактчек

| Симптом | Причина | Проверить | Что делать |
|---------|---------|-----------|------------|
| `Модель вернула пустой ответ` | Модель с рассуждениями истратила лимит на размышления | `grep max_tokens projects/<slug>/config.yaml` | Увеличить `llm.max_tokens` либо взять модель без рассуждений |
| `Ключ доступа не принят` (401) | Ключ неверный, отозван или скопирован не целиком | `grep LLM_API_KEY ~/factory-data/.env` | Скопировать ключ заново из личного кабинета |
| `В ключе доступа есть символы, недопустимые в HTTP-заголовке` | В ключ затесались русские буквы, похожие на латинские | сообщение назовёт эти символы | Скопировать ключ заново, не набирать руками |
| `Закончились деньги на балансе` (402) | Так и есть | личный кабинет провайдера | Пополнить; посты подождут в очереди сами |
| `Адрес или название модели не найдены` (404) | Опечатка в `llm.model` или в адресе | `grep -A3 'llm:' projects/<slug>/config.yaml` | Сверить название со списком моделей провайдера |
| `Модель ответила не по заданной структуре` | Модель плохо держит формат | — | Разовое — система повторит. Постоянное — сменить модель |
| Конфиг не проходит: «требует модель с веб-поиском» | `content.factcheck: strict` при модели без поиска | там же | Указать модель с поиском либо понизить до `light` |
| В заметках фактчека «факты не подтверждены» | Так и задумано: проверка шла без поиска | `grep factcheck_web_search projects/<slug>/config.yaml` | Ничего, если это осознанный выбор. Иначе включить модель с поиском |
| Столбец расходов пуст | Цены не указаны в конфиге | `grep price_ projects/<slug>/config.yaml` | Вписать цены за миллион токенов из кабинета провайдера |

## Telegram-ревью

| Симптом | Причина | Проверить | Что делать |
|---------|---------|-----------|------------|
| Посты не приходят в Telegram | воркер не запущен | `pgrep -f "factory run"` | Запустить: RUNBOOK → «Запустить всё» |
| Посты не приходят, воркер работает | проект в режиме `auto` | `grep -A1 '^review:' projects/<slug>/config.yaml` | Поставить `mode: telegram` |
| `bot can't initiate conversation` | владелец не писал боту `/start` | — | Открыть бота, отправить `/start` |
| `chat not found` | неверный `telegram.chat_id` | конфиг проекта | Узнать число у @userinfobot |
| Кнопки нажимаются, ничего не происходит | не запущен воркер | `pgrep -f "factory run"` | Работу по нажатию делает воркер, не бот |
| «Эта кнопка не для вас» | нажавшего нет в `telegram.reviewers` | конфиг проекта | Так и задумано. Разрешить — добавить число в список |
| «По этому посту решение уже принято» | нажали второй раз или на старое сообщение | — | Ничего: защита от двойного нажатия |
| Один и тот же альбом пришёл дважды | сеть до Telegram отвечает неровно | `tail ~/factory-data/worker.log` | Второй раз картинки не уходят, но текст мог продублироваться; при повторах указать `telegram.proxy_env` |
| Бот не стартует: «Проекты просят разные токены» | в конфигах разные `telegram.token_env` | `grep -r token_env projects/` | Бот один на все проекты — оставить одно значение |
| Бот не стартует: «ни один проект не настроен на ревью» | нет секции `telegram` нигде | конфиги проектов | Добавить секцию либо не запускать бота: в режиме `auto` он не нужен |


## Нажал кнопку, а ничего не произошло

Самая частая жалоба, и почти всегда это не поломка. Бот отвечает на каждое
нажатие — прочитайте ответ, там написана причина.

| Ответ бота | Что это значит | Что делать |
|------------|----------------|------------|
| «Уходит в группу в 19:30» | пост ждёт слота расписания | ждать либо `/schedule_off` |
| «сегодня уже вышло 2 из 2» | исчерпан `limits.posts_per_day` | ждать завтра либо поднять лимит в конфиге |
| «выпуск на паузе» | проект остановлен | `/resume` |
| «ключ загрузки картинок истёк» | ключ ВК живёт сутки | открыть ссылку из сообщения, переслать боту адрес |
| «Пост снова ждёт решения» | состояние поменялось из другого сообщения | кнопки под ним бот уже обновил, нажимайте заново |
| «Пост уже вышел в группу» | отменять нечего | удалять только в самой группе |
| «Эта кнопка не для вас» | вас нет в `telegram.reviewers` | добавить своё число в конфиг проекта |

**Ответа нет вообще** — не работает бот: `pgrep -f "factory bot"`.

**Ответ есть, но пост не двигается** — не работает воркер:
`pgrep -f "factory run"`. Бот меняет состояние, работу делает воркер.

## Не видно списка команд по «/»

Список регистрируется у Telegram при каждом запуске бота. Если выпадашки нет:

1. Проверить, что бот запущен и в логе нет `не удалось обновить меню команд`.
2. Закрыть и открыть чат — Telegram кэширует список.
3. Проверить, что видит сам Telegram:

```bash
grep TELEGRAM_BOT_TOKEN ~/factory-data/.env
# подставить токен вместо <ТОКЕН>
curl -s "https://api.telegram.org/bot<ТОКЕН>/getMyCommands"
```
