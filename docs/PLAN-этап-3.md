# Этап 3: Текст — план реализации

**Цель:** тексты постов пишет настоящая нейросеть, а не заглушка. Шаги `text` и
`factcheck` работают через OpenAI-совместимый API. Картинки остаются заглушками.

---

## Что уже выяснено опытом на RouterAI

Проверено живыми вызовами до написания кода. Эти четыре факта определяют
устройство провайдера.

| Что | Вывод для кода |
|-----|----------------|
| `response_format: json_schema` **работает** | это основной путь получения структуры |
| `response_format: json_object` **не работает** — модель возвращает обычный текст с разметкой | запасной путь строится не на нём, а на инструкции в промпте с разбором ответа |
| Модель с рассуждениями при тесном лимите возвращает **пустой ответ** с кодом 200 | лимит токенов вынести в конфиг, значение по умолчанию с запасом на размышления |
| Пустой ответ внешне неотличим от успеха | считать его сбоем явно, с сообщением «увеличь `llm.max_tokens`», а не падать на разборе JSON |

Замеры: кириллица кодируется примерно по 2,9 символа на токен. Пост целевой
длины (900–1400 символов) плюс заголовок и вопрос — около 550 токенов на выход.

---

## Решения, зафиксированные до начала

| # | Решение | Обоснование |
|---|---------|-------------|
| 1 | Один модуль `openai_compatible.py` на всех совместимых провайдеров | RouterAI, OpenAI, любой реселлер — разница только в `base_url` |
| 2 | `llm.max_tokens` в конфиге, по умолчанию 4000 | заранее неизвестно, впишут ли туда модель с рассуждениями |
| 3 | Цены за миллион токенов — в конфиге проекта | у каждого реселлера свои, и они в своей валюте |
| 4 | Пустой ответ — `ProviderError` с инструкцией, а не ошибка разбора | владелец не программист, «ошибка JSON в позиции 0» ему бесполезна |
| 5 | Свои ретраи провайдер не делает | шаг уже обёрнут в `tracked_call` с тремя попытками |
| 6 | Стоимость считается из `usage` ответа и пишется в `runs` | без этого нельзя ответить, куда уходят деньги |
| 7 | Фактчек **с веб-поиском**, на отдельной модели `perplexity/sonar` | проверено живьём: модель без поиска одобрила текст с ошибкой в сто раз |
| 8 | Источники из ответа фактчека сохраняются в `factcheck_notes` | если текст исправлен, владелец должен видеть, на каком основании |

### Почему фактчек — отдельная модель

Проверено на тексте с двумя заведомыми ошибками (штраф 50 000 ₽ вместо 500 ₽,
неверный год):

| Модель | Вердикт | Итог |
|--------|---------|------|
| `perplexity/sonar` | `fixed` | нашла обе ошибки и исправила |
| `deepseek/deepseek-v3.2` | `ok` | одобрила текст, уверенно сославшись на приказ Минтранса |

Фактчек без поиска не просто бесполезен — он вреден: создаёт ложное чувство
проверки. Модель без доступа к источникам обязана отвечать `uncertain`, а не
`ok`, но заставить её так делать надёжно нельзя. Поэтому проверка модели вынесена
в валидацию конфига.

## Что выяснилось по ходу

**Стоимость вообще не записывалась.** Дыра жила с Этапа 1: `tracked_call` читал
цену с того, что вернул шаг, а шаг возвращает `StepResult` — цена оставалась на
ответе провайдера внутри шага. Пока провайдеры были заглушками с нулевой ценой,
пустая колонка выглядела правдой. Теперь стоимость копится в контексте шага
(`ctx.charge`), пять тестов не дают этому вернуться.

**Лишняя ветка в разборе ответа.** Мутация «не доставать JSON из блока разметки»
выжила — оказалось, поиск по фигурным скобкам покрывает тот же случай. Убрал
дублирующий код вместо того, чтобы дописывать тест на него.

**Два теста проверяли не то, что заявляли.** После разделения моделей тест
повторного фактчека считал обращения к модели текста, куда фактчек не ходит
вовсе. А тест промптов сверял константы между собой, не проверяя, какую из них
шаг реально отправляет. Обе дыры нашли мутации.
